### Finding A — Gate 2 regression, isolated to Slice 2

Direct comparison, same tree, two commits:

| Commit | State | Unsafe sites w/ SAFETY |
|---|---|---|
| `f3519dc` (Slice 1, pre-fmt) | `cargo run -p fjell-unsafe-audit` | 274 / 274 |
| `c0f5b9c` (Slice 2, post-fmt) | `cargo run -p fjell-unsafe-audit` | 270 / 274 |

Missing at `c0f5b9c`:

```
./crates/fjell-kernel/src/main.rs:416 [block]
./crates/fjell-kernel/src/main.rs:422 [block]
./crates/services/fjell-recoveryd/src/main.rs:20 [block]
./crates/services/fjell-recoveryd/src/main.rs:34 [block]
```

Root cause, `crates/fjell-kernel/src/main.rs` (pre-fmt → post-fmt):

```rust
// pre-fmt (f3519dc) — comment and `unsafe` are adjacent
macro_rules! ks_init {
    // SAFETY: category=phys-id-map-assumption ...
    ($ks:expr, $val:expr) => { unsafe { (*$ks.0.get()).write($val) } };
}

// post-fmt (c0f5b9c) — fmt expanded the arm; `unsafe` is now two lines
// below the comment
macro_rules! ks_init {
    // SAFETY: category=phys-id-map-assumption ...
    ($ks:expr, $val:expr) => {
        unsafe { (*$ks.0.get()).write($val) }
    };
}
```

Same pattern in `fjell-recoveryd/src/main.rs`: `fn send_ready() { unsafe { ... } }`
(one line, comment directly above) became a 3-line function, again
separating the comment from `unsafe` by one line.

### Finding B — Gate 4 failure, pre-existing, unrelated to formatting

`cargo run -p fjell-abi-snapshot -- --verify`:

```
Baseline items : 401
Current items  : 375
Added          : 3 (additive — OK)
Removed        : 28
Changed sig    : 161  (whole-tree fmt shifted line-based sig hashes — expected, see docs/src/abi/policy.md)
```

All 28 "removed" items belong to exactly two crates —
`fjell-audit-format` (16 items, e.g. `AUDIT_LOG_MAGIC`, `AuditKind`,
`AuditEvent`) and `fjell-bundle-format` (11 items, e.g. `BUNDLE_DOMAIN`,
`BundleError`, `ServiceBundle`) — plus one further item. I confirmed all
are still present in source, e.g.:

```
crates/formats/fjell-audit-format/src/lib.rs:264:pub const AUDIT_LOG_MAGIC: [u8; 8] = *b"FJLAUDIT";
crates/formats/fjell-bundle-format/src/lib.rs:49:pub const BUNDLE_DOMAIN: &[u8] = b"FJELL-BUNDLE-V1";
```

Cause: `tools/fjell-abi-snapshot/src/main.rs`'s `STABLE_CRATES` table:

```rust
const STABLE_CRATES: &[(&str, &str)] = &[
    ("fjell-sdk", "crates/fjell-sdk/src"),
    ...
    ("fjell-audit-format", "crates/fjell-audit-format/src"),   // stale: moved to crates/formats/ in v0.21.0
    ("fjell-bundle-format", "crates/fjell-bundle-format/src"), // stale: moved to crates/formats/ in v0.21.0
];
```

Both paths predate the v0.21.0 crate subdirectory reorganization
(`a5b5167`) and were never updated. The scanner finds nothing at the
stale path, sees zero current items for each crate, and reports every
previously-snapshotted item as removed. This has nothing to do with
`cargo fmt` and predates `5091e54`; it was masked because no `cargo`
command has run to completion since the reorg landed close to the
outage. This is Risk R1 from the RFC materializing ("restoring the build
reveals further latent breakage masked by M1").

## 7. Unresolved issues and blocked items

Both below block a meaningful Slice 3 (its acceptance criteria include
"Gate 4 reports zero ABI removals" and no Gate 2 regression) and both
require a scope decision I'm not authorized to make unilaterally, since
neither is listed in the handoff's change scope and one touches a file
(`crates/fjell-kernel/src/main.rs`) the handoff explicitly excludes:

1. **Finding A (Gate 2, 2 kernel sites + 2 service sites).** Candidate fix
   is comment-only: move each `// SAFETY:` comment to sit immediately
   above its `unsafe` token. No logic changes. Blocked because
   `crates/fjell-kernel/src/main.rs` is in the handoff's explicit
   non-change scope, and the handoff's instruction on gate regressions
   from fmt is "escalate," not "fix."
2. **Finding B (Gate 4, `fjell-abi-snapshot` stale paths).** Candidate fix
   is a two-line path correction in `tools/fjell-abi-snapshot/src/main.rs`
   (`crates/fjell-audit-format/src` → `crates/formats/fjell-audit-format/src`,
   same for `fjell-bundle-format`). No ABI semantics touched — the tool
   would then report the true current surface (401 baseline items were
   generated pre-reorg; re-running `--generate` afterward would need its
   own review, since the RFC's non-goal "No removal from the ABI enum"
   suggests the snapshot itself may need architect sign-off on any
   resulting diff). Not listed in this RFC's scope.

I have not modified either file pending direction.
