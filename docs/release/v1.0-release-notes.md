# Fjell OS v1.0.0 — Release Notes

## What this release is

Fjell OS v1.0.0 is the first supported **QEMU profile** of a Rust-first,
capability-based microkernel OS with lease-bounded authority, semantic
observability, signed-bundle foundations, selective Verus machine-checked
invariants, and fail-closed QEMU negative tests for the covered security
boundaries.

This release should be read as a carefully scoped, honest milestone — not
as a broad production operating system.

---

## Supported profile

**QEMU `virt` (`riscv64gc-unknown-none-elf`)** — the one validated profile.

The StarFive VisionFive 2 board profile is provisional and has not been
booted on silicon (E-004, accepted v1.0 limitation).

## What is covered and verified

| Claim | Evidence |
|-------|----------|
| Capability authority never amplified (mint path) | Verus machine-checked, 8 obligations; conformance tests; property tests |
| Lease epoch revocation is bounded and monotonic; retire-before-wrap at u32::MAX | Verus machine-checked, 5 obligations; C6 ABI helper; retire-before-wrap conformance tests |
| BCB mirror selection is total and deterministic | Verus machine-checked, 7 obligations; conformance tests |
| Capability refusal paths exercise real kernel enforcement | 8 QEMU negative markers, fail-closed |
| MMIO guard, DMA rights, audit evidence, user-copy, policy, IPC revocation, service lifecycle | 19 additional QEMU negative markers, fail-closed |
| IPC lease-revocation protocol (BLOCKED_RECV, BLOCKED_CALL, LATE_REPLY) | 3 QEMU negative markers; kernel reply-edge cancellation implemented (RFC 050) |
| Unsafe sites annotated with SAFETY justifications | 208 kernel sites, zero missing |
| MMIO writes annotated with ordering justification | Zero missing MMIO-ORDER annotations |
| ABI stability checked | Snapshot gate (no removals) |
| Reproducible build | Two-build SHA-256 comparison, 28 artefacts |
| Trust-anchor provisioning requires explicit flag | `cargo xtask provision-dev --allow-tofu-provision` — refuses without it |

## What is explicitly NOT claimed

### Hardware

This release does not claim real-hardware readiness. No v1.0.0 workload has
been booted on physical silicon. The VisionFive 2 profile is provisional.
Hardware bring-up is tracked for v1.1.

### Formal verification

The Verus proofs cover three narrow, pure-logic invariants: capability
non-amplification, lease epoch revocation, and BCB mirror selection. They do
not cover the full kernel, the IPC implementation, the service-manager, or
any concurrent execution path. Verus was not applied to the IPC words or
reply-edge code that was found defective and fixed in v0.20.0.

The correct claim is:
> The *predicates* governing capability minting and lease revocation are
> machine-checked. The *implementation paths* that invoke those predicates
> are unit-tested, property-tested, and QEMU-negative-tested. They are not
> formally verified end-to-end.

### Store and upgrade negative coverage

The `store` and `upgrade` negative profile specifications exist (8 markers
total) but have no runtime-emitting implementation. They are not v1 release
gates. Storage integrity and upgrade verification are core to Fjell's
identity; full negative coverage for these paths is a v1.1 target.

### Service-manager lifecycle coverage

The service-manager negative profile covers START_TIMEOUT and FAULT_DETECTED
(2 of 4 expected markers). The READY pair (`READY_ACCEPTED`,
`UNAUTHORIZED_READY_REJECTED`) is timing-sensitive and not yet reliable.
Partial coverage is accurate coverage; full coverage is a follow-up target.

### Trust-anchor production lifecycle

The dev/QEMU profile supports TOFU provisioning with an explicit flag
(`--allow-tofu-provision`). Silent default TOFU is prohibited. However, the
signing-side coupling is currently operational rather than enforced: the
operator must also sign bundles with the provisioned authority's key; no gate
verifies this correspondence. Factory-station provisioning (v1.1) and
hardware-anchored provisioning (v2+) are not yet implemented.

### POSIX compatibility

Fjell OS has no POSIX surface. No descriptors, fork, signals, or ttys.
This is a permanent non-goal (N1).

### General-purpose OS

Fjell OS is not a general-purpose operating system. v1.0 targets A1
(industrial gateways), A2 (fleet nodes), and A3 (regulated devices) as
defined in RFC 061. General-purpose workloads are outside scope.

## Known limitations (Gate 9 reference)

The six items below are the accepted v1.0 limitations. Any party signing
Gate 9 is accepting these explicitly.

| # | Limitation |
|---|------------|
| 1 | **Hardware** — no validated real-hardware deployment; VisionFive 2 profile is provisional |
| 2 | **Multi-hart** — single-hart only; SMP is a post-v1.0 milestone |
| 3 | **POSIX** — no POSIX surface; permanent non-goal |
| 4 | **Kernel-IPC SDK reference service** — reference service does not use live kernel-mediated IPC (non-goal N21) |
| 5 | **ZeroizeOnDrop** — no independently verified byte-level key-erasure guarantee (non-goal N23) |
| 6 | **Trust-anchor provisioning** — dev/QEMU TOFU requires explicit `--allow-tofu-provision` flag; end-to-end provision/sign/verify workflow is a v1.1 requirement |

Additional operational notes:

- Store and upgrade negative profile specifications are not v1 release-gated.
- svc READY pair coverage is partial (2/4; timing-sensitive).
- Several services in the QEMU image are smoke-test stubs that signal ready
  and exit by design (`fjell-netd`, `fjell-driver-virtio-net`, and others).

## What changed since v0.18.3 (brief)

v0.19.0 converted all nine QEMU negative categories from RFC 025 placeholders
to real kernel-boot tests and found six latent kernel bugs in the process.
v0.20.0 made those tests fail-closed, which exposed two further defects: an
IPC words ABI bug (payload words silently dropped since the protocol's
introduction) and a missing reply-edge cancellation on lease revocation. Both
have been fixed. The IPC negative profiles now exercise the real blocking
protocol for the first time.

See `CHANGELOG.md` for full details.
