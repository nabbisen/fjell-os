## What shipped

### RFC-0.30-001 — the reproducibility check compared a file to itself

`fjell-repro-check`'s two-build mode ran `cargo xtask build` twice with no
clean between them, so the second build was an incremental no-op and the
comparison was between a file and itself — measured at **0.41s and 0.40s per
"build"**. A genuine two-build run (a scoped `cargo clean` before each) costs
**4–7 seconds total**, not the "doubles CI build time" the RFC assumed
before anyone timed it; it now runs in CI on every push. Two independent
runs produced bit-for-bit identical output across all 30 artefacts — this
project's same-machine build is, as measured, reproducible.

Closes **E-036**.

### RFC-0.30-002 — four subchecks that failed without saying which

With an RFC lifecycle folder absent, four of Gate 12's subchecks failed with
a bare, unnamed `cannot read …` line. `handoff-status`'s filed defect
("silent") was found to be wrong on inspection: it either produced the same
unnamed message or — worse — **passed incorrectly**, blind to the missing
folder because it only ever touched lifecycle folders incidentally. Every
subcheck's I/O failure now names itself, applied to all ten subchecks that
existed at the time. Separately, `fjell-abi-snapshot --verify` now fails on
any non-zero `Added`, moving the ABI-surface enumeration to the line that
makes the addition rather than deferring it to the next cut.

Closes **E-035** and **E-038**.

### RFC-0.30-003 — the toolchain was declared in twenty-two places, recorded in none

E-037 said five places; measured, it was **twenty-two**. On 2026-09-09,
`rust-toolchain.toml` was removed and local builds silently moved from
**1.91.1 to 1.98.1**; the detector fired and could not say why. All three
artefact-producing paths now record the toolchain **observed** at production
time (`rustc -vV`), never the declared channel. A new
`toolchain-declarations` subcheck compares every live declaration site
against `rust-toolchain.toml` and fails naming exactly which one was left
behind at a bump.

**E-037 narrowed, not closed** — two named, coupled survivors: still 22
places to edit at a bump, and the channel remains unpinned (an exact pin
would itself break the new drift check against Ubuntu's unversioned `apt`
package names).

## The implementer's own findings this cut, recorded

Consistent with this project's practice of recording its own errors rather
than smoothing them over:

1. **A real instance of the standing handoff's trap 6.** The three RFC
   `git mv` renames (accepted/ → done/) landed in the "rebuild the repro
   baseline" commit rather than the "move the RFCs" commit that followed —
   `git mv` stages a rename immediately, and a subsequent plain `git add
   <other files>` does not touch it. Caught by reading the actual commit
   contents afterward, not before. No wrong content resulted — the Status
   and link corrections landed in the very next commit — but the commit
   boundary did not match its own message, which is exactly what trap 6
   warns is easy to miss. Checked `git diff --cached --name-only` before
   every commit after this one.
2. **The 177→180 `rfcs/README.md` file count was re-derived, not assumed**,
   against `ls rfcs/done/*.md | wc -l` — it matched the cut handoff's own
   figure exactly, the first re-derivation this session where nothing needed
   correcting.

## What this release does not claim

- **Not that builds are reproducible across machines or time** — same-machine
  reproducibility is now measured and demonstrated (RFC-0.30-001); the
  toolchain is now recorded on every artefact (RFC-0.30-003), but nothing
  compares two machines' digests against each other, and the channel is
  unpinned.
- **No conformity with anything** — 15 of the standards mapping's 37 rows are
  `unassessed`, the IEC standards being paywalled and unread.
- **No hardware.** Nothing here has run on silicon.
