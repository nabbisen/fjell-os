## Known limitations at 0.21.3

Carried forward from the RFC-v0.21.3-001 review chain, unresolved by
design (each has an explicit disposition, not silently dropped):

| Limitation | Disposition |
|---|---|
| 9 of 28 prebuilt service binaries can rebuild to different bytes with no source change (same file size); confirmed cross-environment, not within-environment, via a real two-build check (29/29 identical in one environment) | v0.22, its own RFC (build/link determinism) |
| The ABI snapshot gate is formatting-sensitive by design (line-based signature hashing); a whole-tree `cargo fmt` invalidates it wholesale | v0.22 candidate list |
| 9 syscalls declared in `fjell-abi` but not dispatched (`CapInstall`, `PlatformReboot`, `TaskKill`, `MmioUnmap`, `IrqBind`, `IrqAck`, `IrqWait`, `DmaShare`, `Reboot`); each fails closed to `UnknownSyscall` | v0.22, disposition (implement / remove from ABI / keep reserved) not yet decided |
| `sys_cap_install_with_rights` doc-comments describe a kernel rights check that cannot execute, because `CapInstall` is not dispatched at all | ERRATA E-011 (ACCEPTED), `docs/release/v1-limitations.md` item 7 |
| Step 9 of the v1.0 release checklist assumes `target/release-bundles/*.bundle` exists as a build output; no reference to that path exists in `package_release.rs` | Not investigated this release line; flagged for review, v1.0-checklist-specific so does not block a v0 release |

Unaffected by this release: all v1.0-scoped limitations in
`docs/release/v1-limitations.md` (hardware, multi-hart, POSIX, kernel-IPC,
ZeroizeOnDrop, trust-anchor provisioning, `cap_install`) — this is a v0.x
patch release, not `v1.0.0`; Gate 9 remains unsigned and out of scope.
