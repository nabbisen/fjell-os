## Findings resolved during this line

Both were surfaced by this RFC's own checks (Slice 4's `rfc-status-folder`
and the interaction with the pre-existing Gate 7), reported rather than
fixed by the implementer per handoff §6, and dispositioned by the
architect on review — recorded here so the evidence stays re-derivable.

### Finding 1 — RFC-v0.17-001 status/folder disagreement

`rfcs/done/RFC-v0.17-001-trust-anchor-provisioning.md` sat in `rfcs/done/`
with `Status: Accepted (design options — requires architect decision)` —
staler than the implementer's own report showed: the decision it named
was recorded 2026-06-04, and that decision's v1.0-tier deliverable (the
`--allow-tofu-provision` TOFU flag) shipped in v0.20.0. The field
announced it was waiting for something already made and shipped two
release lines earlier, through multiple prior reviews.

**Resolved:** corrected to `Implemented (v0.20.0)` (architect, 2026-07-31),
with an explicit deferred note for the remaining tiers (factory-station
v1.1, hardware-anchored v2+) per RFC 000's partial-implementation rule.
Gate 12's `rfc-status-folder` subcheck now passes against this file.

### Finding 2 — erratum E-012 classification

E-012 (the v1.0 checklist Step 9 finding) was recorded `OPEN` by the
implementer, which correctly tripped the pre-existing Gate 7 ("0 OPEN"
errata). Architect review concluded Gate 7 itself should not change
(scoping it by release line would create a new way for drift to hide),
but the classification was wrong: declining to investigate E-012 was a
deliberate owner decision (2026-07-30, v1.0 not in view), which is
`ACCEPTED` semantics under this register's own legend — the same grounds
on which E-004 is `ACCEPTED`.

**Resolved:** reclassified `ACCEPTED` (architect, 2026-07-31), attributed
and dated in `docs/rfcs/ERRATA.md`, and recorded in
`docs/release/v1-limitations.md`'s operational notes as Gate 12's
`errata-limitations` rule requires. Gate 7 now passes.

### New finding, tracked for v0.23 (not acted on here)

Architect review identified that `ACCEPTED` in the errata register has no
gate of its own — no owner-acknowledgement requirement, no review-by
date — so reclassifying `OPEN` → `ACCEPTED` is structurally the path of
least resistance whenever Gate 7 is red. The current three `ACCEPTED`
entries (E-004, E-011, E-012) are each genuinely deliberate; the concern
is the structural pressure, not present contents. Candidate remedies
(explicit owner acknowledgement per item; a review-by milestone that
re-fails the gate once passed) are recorded as a v0.23 candidate, not
decided here.
