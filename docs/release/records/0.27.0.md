## What this release is

A milestone spent on one question: **which of this project's documents assert
something nothing verifies?**

The answer was: most of them. Gate 12 entered this release running **4**
consistency subchecks and leaves running **10**. The errata register entered at
**23** entries and leaves at **30** — not because the project got worse, but
because seven divergences that already existed became visible.

No kernel behaviour change. One ABI-surface rename (`sys_ipc_try_send` →
`sys_ipc_send`), reconciled as exactly one removal and one addition.

## Two procedure gaps this cut found by breaking

Both are now written into the cycle. Recorded here rather than fixed silently,
because a step that is known and unwritten is rediscovered as a failure — which
is exactly what happened to the repro baseline at 0.24.0.

### The version is written twice, and nothing checks the two agree

Bumping `[workspace.package] version` to `0.27.0` left
`crates/fjell-os/Cargo.toml:14` requiring `fjell-abi 0.26.0` from a workspace
that now contained `0.27.0`. `cargo metadata` failed — **exit criterion 1, the
one the cycle says makes every other criterion unevaluable.**

A path dependency needs an explicit `version` to be publishable and Cargo cannot
inherit the workspace package version into a dependency requirement, so the
string is hand-maintained. `version-currency` checks `README.md`; it does not
see this pair. Filed as **E-030** (ACCEPTED, `0.28`) rather than fixed here,
because extending a subcheck carries RFC-v0.22-001's demonstration requirement
and that does not belong inside a cut. **Fail-closed**: a mismatch stops the
workspace resolving, so it costs time, not correctness.

### Recording the repro baseline before rebuilding produces a clean-looking lie

The first attempt recorded the baseline immediately after the version bump.
`git diff --numstat` came back **empty** — which reads as a clean result and is
actually the failure: `--skip-build` had recorded the digests of the *existing*
`0.26.0`-era binaries.

After `cargo xtask build`, the diff was what it should be:

```
$ git diff --numstat tests/repro/baseline-digests.txt
1       1       tests/repro/baseline-digests.txt
-0281a84f… crates/fjell-kernel/prebuilt/fjell-neg-test.bin
+6a936150… crates/fjell-kernel/prebuilt/fjell-neg-test.bin
```

**Exactly one line, for the one binary the version bump moved** — the same
binary, and the same reconciliation, as the 0.24.0 cut. Order is now written
down: bump → build → delete → re-record → verify.

## Criterion 8 — what re-reading by hand found

Gate 12 confirms every cited path exists. It does not confirm the citing row is
still true, and the cycle says so. Two things were wrong:

1. **`crates/fjell-os/README.md`** — the crates.io landing page — stated the
   register carries *"13 accepted limitations and 0 open"*. E-030 made it 14.
   This is the copy outsiders see first.
2. **`docs/release/v1-limitations.md` item 7** stated *"`CapInstall` and the
   other **8** declared-but-undispatched syscalls deferred to v0.22."* The count
   had moved — there are **6** undispatched in total (`CapInstall`,
   `PlatformReboot`, `TaskKill`, `MmioUnmap`, `DmaShare`, `Reboot`), so it is
   the other **five** — and the deferral was to a milestone that shipped five
   releases ago without it. Corrected to state the real figure and that the
   disposition remains open.

Neither was caught by any gate. Both were caught by opening the file, which is
what criterion 8 is for.

### A milestone commitment this cut refused to let pass

**E-025** was scheduled for 0.27 at the RFC-0.27-002 review. 0.27 shipped
without it. `errata-tracking` — RFC-0.27-001's own subcheck, shipped in this
same release — blocked the cut:

```
errata-tracking: FAIL
  E-025: tracking names milestone 0.27, which has already shipped,
         but status is "ACCEPTED" (not CLOSED)
```

Rescheduled to 0.28, with the slip recorded in the erratum rather than the date
quietly changed. **This is the third time this milestone one of these subchecks
has fired against the architect rather than the implementer** — `errata-tracking`
on E-022's tracking field, `doc-links` on a handoff link surviving a `git mv`,
and now a scheduling commitment that was not met. That is the intended
direction: the instruments exist because the person writing the documents is
the person least able to see their drift.

### Three corrections to how this project reasons

- **Log interleaving does not prove blocking.** `trap_dispatch` calls
  `schedule_next` after *every* trap, so "task B ran in between" is consistent
  with either outcome. Blocking is now read from the kernel's audit ring.
- **A `met` against an unread criterion is not a status.** Ten of fifteen IEC
  rows carried verdicts against paywalled text. All fifteen are `unassessed`,
  enforced by rule.
- **Evidence must outlive its run.** Every kernel claim this project had ever
  made cited a file that no longer existed.

## Known limitations carried into this release

**30 errata: 0 OPEN, 16 CLOSED, 14 ACCEPTED.** Full text in
[`docs/rfcs/ERRATA.md`](../../rfcs/ERRATA.md); the reader-facing set is
[`docs/release/v1-limitations.md`](../v1-limitations.md).

The ones a reader should know about:

- **E-013** — `fjell-kernel` has no `[lib]`, so nothing kernel-side is
  host-testable. This is why E-026 mattered and why `tests/evidence/` now exists.
- **E-024** — `init` still co-receives on four services' own endpoints, and
  RFC-0.26-004's one-receiver invariant is narrower in the tree than in its own
  text. Load-bearing as it stands.
- **E-025** — the trust-report scan walks untracked scratch directories and can
  double the reported unsafe inventory, plausibly and silently.
- **E-029** — two historical QEMU citations remain unresolvable, annotated
  rather than re-manufactured, tracked to 0.28.

## What this release does not claim

- **No conformity, compliance or certification with anything.**
  `docs/compliance/standards-mapping.md` maps mechanisms to clauses and states
  evidence. Only a conformity assessment can establish conformity. Fifteen of
  its 37 rows are `unassessed` because IEC 62443-4-1/4-2 are paywalled and
  unread.
- **No hardware.** Nothing in this release has run on silicon.
- **No claim that a committed log proves its document's reading of it.**
  RFC-0.27-004's disclosure, in three places.
- **RFC-0.26-003 (E-019) did not ship.** It remains accepted and unstarted.
