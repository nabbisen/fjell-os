## What shipped

### RFC-0.43-001 + Amendment 1 — the solver pin is enforced (closes E-112)

`TOOLCHAIN.lock` recorded a `[z3]` version that `verus-check` never compared, so the 0.42 upgrade
moved z3 **4.12.5 → 4.16.0** with nothing noticing. The solver is now read from the binary the
prover will actually run, and **both pins block in every mode**, including a version that cannot be
*established*. The `[z3] path` field is **deleted** rather than corrected — right for one install
route, wrong for the other.

**Amendment 1 exists because enforcing the pin made the procedure the pin governs unperformable.**
A new prover bundles a new z3, so nothing could run the proofs until the pin moved, while the lock
says the pin moves only behind a recorded re-run. `verus-check --candidate` runs the proofs under a
mismatched pin, emits `CANDIDATE-ONLY` and **never** the machine-checked marker, and is refused
under `--release-required`. Rehearsed end to end on a copy of the lock.

*The implementer also narrowed E-112: Verus has its own solver check, so "no gate noticed" was too
strong — a mismatched solver would have been refused for the Verus release it shipped with.
Established by experiment, not from the flag's name.*

### RFC-0.43-002 — every declaration is visible to the instrument that checks it (closes E-117)

`capability-topology` discovered `CapHandle` declarations in **one hard-coded directory**, so nine
of nineteen sat outside its universe and a constant planted in `crates/drivers/` **passed
silently** — the defect that forced the module's rewrite once before, on a different axis. Its
slot-0 exclusion was justified by a `_ => 0` fallback RFC-0.41-002 had deleted. Discovery now walks
every crate and **fails rather than skips** on a non-spawnable one; slot 0 is judged; two waivers
print their reasons.

### RFC-0.43-003 — `driver-virtio-net` says only what it does (closes E-118)

The image was spawned every boot, called `sys_irq_bind` on a slot nothing installed, and exited —
and printed *"device descriptor loaded"*, *"features negotiated"* and *"rx queue initialised"* with
**`sys_mmio_map` never called in the crate**. `IRQ bind failed` sits in **5,075 retained artefacts**
going back to **2026-07-31**, unread, because `netd` emits the v0.4 net marker without needing the
driver. Now a **44-line stub** — 1030 → 177 bytes — that says what it is and exits 0; the MMIO
region grant is removed from **both** stub drivers.

**Not a decision against a real NIC driver.** That needs an authority design and is neither taken
nor foreclosed. What was refused is shipping an image that claims to do it.

### RFC-0.43-004 — the milestone's RFCs move by one command (narrows E-116)

See *Step 7*. Validated by promoting a worktree of the **real 0.42.0 cut** and comparing
byte-for-byte with the hand result — which caught a bug no unit test had: the Implemented section's
closing rule is the *last* `---` before the next heading, not the first.

## Exit criterion 8 — what it found

**One finding, and it is the reason this criterion is a hand re-read rather than a gate.**

A dated **E-082** account in `v1-limitations.md` stated that `driver-virtio-net` *"is also not one
of these"* — not an early-exit stub — because *"`service_main` reaches a real
`loop { sys_irq_wait(...) }` after binding its IRQ"*.

**It never bound its IRQ.** The call hit a slot nothing installed and failed on every boot, so the
loop was never reached — and `IRQ bind failed` was already in retained artefacts from **2026-07-31,
before that sentence was written**. The judgement was read off the source's *structure* and
contradicted by every log in the tree: the structure was real, and the behaviour was the opposite.

**It also inverted a comment that was accidentally right.** RFC-0.37-002 deleted the crate's top
comment for *"independently and falsely"* claiming an early exit "by design". The image did exit
early — **not by design but by failure** — so the comment was wrong about the reason and right
about the behaviour, and the correction removed the true half.

Annotated as a dated record rather than rewritten, with the finding added to **E-118**.

## What this release does not claim

- **No security advisory.** The kernel has never been distributed as a runnable artefact and the
  product has not been placed on the market.
- **The Clock gate's rights check is demonstrated by nothing** — row 18 says so. The new case
  proves refusal for *no authority* and *wrong kind*; weakening the required right to `NONE` leaves
  it passing, because that needs a `Clock`-kind capability lacking `CLOCK_READ`. Scheduled.
- **A boot can create at most 32 leases, ever** (row 21, **E-110**).
- **Authority cannot be withdrawn from a task without ending it** (row 12, **E-093**).
- **Three of the measurement chain's four events are placeholders** (**E-095**) — unscheduled on
  size and development-grade crypto, **not blocked**: an anchor and a verification path both exist,
  and the register now says so after the previous reason proved false.
- **`doc-counts`' five-count rule is implemented twice**, once in the subcheck and once in
  `rfc promote`'s pre-flight. Disclosed by the implementer, pinned by a test, scheduled for
  removal.
- **Hardware, multi-hart, POSIX, kernel-IPC, ZeroizeOnDrop and trust-anchor provisioning** remain
  as rows 1–6 state.
