## What this release is

Four RFCs, **four errata closed** (**E-096**, **E-097**, **E-098**, **E-099**).
The measurement chain's `source` is derived from the kernel-attested sender instead
of the caller's word, so three events per boot stopped claiming a service that had
no part in them. The chain head is readable by `diagnosticsd` and published in the
signed bundle beside two counts that say how much of the chain the kernel actually
digested — one of four — so making it readable does not let a mostly-placeholder
chain read as measured. And two memory defects close.

**0.39.0 closed a cross-task memory hole that was live from v0.8.x through 0.38.0**
(**E-099**): a revoked DMA frame returned to the general pool with the revoking
task's `R`/`W`/`U` mapping intact, so a DMA-capable service (`STORAGED`,
`DRIVER_VIRTIO_BLK`, `NEG_TEST`) could read and write another task's memory. **The
same applies to E-097**, over the same window: the kernel's 4 MiB stack was only half
reserved in the frame allocator, so the allocator handed tasks frames the kernel stack
then overwrote on every trap. Both are stated in the CHANGELOG in the architect's
required terms. There is **no security advisory** — the architect's ruling
(`.git-exclude/reviewed/review-record-rfc-0.39-004-implementation.md` §5) is that the
channel exists so users of shipped software can act and there are none; that ruling
changes if anyone ever deploys 0.38.0 or earlier.

**What still does not hold, in the same breath:** the signed attestation record is
independent constants (**E-094**); three of the chain's four events are placeholders
(**E-095**); and the frame allocator's own unit tests are run by no gate (**E-100**).
Publishing the head does not make attestation real, and does not make the chain fully
measured.

## What shipped

### RFC-0.39-001 — the chain records who actually said it (closes E-096)

`measuredd` derives an event's `source` from the operation plus the kernel-attested
sender: `init` records as the new `Init`, eleven services record themselves, every other
appender is refused with no default arm, and a non-zero declared source byte is refused
rather than ignored. `APPEND_IMAGE_SET` is `init`-only. An unknown kind or subject byte is
refused instead of being recorded as the chain's most load-bearing kind. `MeasurementSource`
means *who produced the measured fact*.

### RFC-0.39-002 — the head is readable, and says how much of it is real

`DIAGNOSTICSD` slot 4 is a `CALL`-only capability to `measuredd`; the signed bundle
(`DIAG_BUNDLE_VERSION` 4) carries the head plus `measurement_event_count` and
`measurement_events_kernel_digested` (4 and 1), a *structural* count of the events whose
digest arrived by the path where the kernel produced it. `remote-diag` asserts the head
against an independent host derivation. `capability-topology`: 4 installed / 2 waived →
**5 installed / 1 waived / 6 checked**.

### RFC-0.39-003 — find out why a live page reads as zeros (closes E-097, E-098)

The kernel's 4 MiB stack was only half reserved in the frame allocator. The whole stack is
reserved, `kmain` refuses to boot if any frame under `__stack_top` is free, the allocator
has a real owner map, and the four DMA release sites share one checked helper. Under an
fsync storm the failure went from 19 of 20 to 0 of 40.

### RFC-0.39-004 — a revoked frame stops being reachable (closes E-099)

`sys_dma_revoke` reads the owner's PTE, requires it to be the recorded frame, unmaps,
requires the removed frame to match, flushes the TLB, zeroes and reads back, then frees.
If the unmap cannot be verified nothing is zeroed or freed. The new `dma` scenario asserts a
read through the revoked address *faults*. The frame-identity check never fired in any run.

## What this release does not claim

- **That the measurement chain attests the system.** One event of four is a real
  measurement, of the embedded service images only. The other three record `0xAB` (E-095).
- **That an attestation record says anything about the chain.** `attestd` signs constants
  and holds no route to `measuredd` (E-094); `last_attestation_available` stays `false`.
- **That the chain head in the bundle is "how much is trustworthy".** The second count is
  structural: events whose digest the kernel produced. It cannot describe the others.
- **That no other frame is wrongly free.** The boot invariant covers the kernel image and
  stack only. The frame allocator's unit tests are run by no gate (E-100).
- **That a task exiting leaks nothing.** Reclaiming task memory in general is E-093.
- **That a bundle can leave the node**, unchanged since 0.37.0.
- **That a clean dependency check describes what Fjell OS ships.** The published crates and
  the kernel have no third-party dependencies; the check covers tools, tests and the
  development-grade crypto crate, and says so itself.
- **That CI gates the release.** Criteria 9 and 11 *record* CI; every gate runs locally.
- **Cross-machine reproducibility**, as at every previous release.
