## What shipped

### RFC-0.34-004 — a word that claims an authority it does not carry

`fjell-semantic-stream`'s `DISPATCH_ACTION` authority check compared a
required capability against an ordinary IPC payload word a presentation
sent, under a comment asserting the value was kernel-verified — true on the
presentation's own side, confirmable nowhere on the receiving one. The
payload word is now never read: the decision is a lookup against the
kernel-attested sender's own compiled-in policy row
(`CapRights::PROXY_TEXT_DEMO`, one constant both the kernel's capability
install and the stream's policy read). A forged claim of every right there
is — demonstrated in a committed tier, `semantic-liar`, a presentation
installed with no dispatch capability at all — is refused every run; the
identical forgery was accepted before the fix. The four `send` helpers
E-034 named no longer take a payload word that was never carried to a
receiver in the first place. Dispatching an action still does nothing.
Closes **E-059**, **E-034**.

### RFC-0.34-005 — the presentation in the threat model

`docs/src/security/threat-model-v1.md` enumerated twenty threats and named
none of them a proxy or a presentation, despite the component receiving
every operator-facing byte and an archetype (**A4**) now depending on it.
Three entries close the gap: **T21**, the authority-claim instance this
release also fixed; **T22**, an absent or crashed presentation stalling the
node's narration, with five named survivors; and **T23**, the first entry
in this model whose adversary's target is a person rather than a task — a
compromised presentation showing false state to the attending operator —
for which **no defence exists**, named as a residual rather than asserted
away. The model covers only a presentation on the same node; one on a
separate or personal device remains named and excluded. Closes **E-060**.
