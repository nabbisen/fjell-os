## What this release is

0.49 made the ABI promise only what it does. **That rule was applied to the two source files
`syscall-surface` reads.** This release applies it to the three other places the same promise is made:
**the documents a service author reads**, **the kernel logic no test ever compiled**, and **the syscall
0.49 built that nothing then used.**

Three lines, four small items, **E-135 closed, E-137 and E-138 filed**. `consistency-check` goes from
**30 to 34 subchecks**; `test-all` from 37 to **38 tiers**; host tests from 996 / 1719 to
****1081 lib / 1810 bins****.

**And the one figure in the v1.0 readiness matrix that matched nothing is settled.** The Verus row
promised *"20 obligations machine-checked"* from v0.18.1 against `verus-count`'s four figures —
**19 / 26 / 12 / 17**. The owner ruled **19** on 2026-11-27, after the architect's recommendation had
stood unresolved for **eight milestones**. The word *"obligations"* went with it: it named no measured
quantity, which is how a figure matching nothing survived inside the release gate while
`readiness-summary` passed — that subcheck compares the table's counts with its rows, and never a row's
prose with the tool that owns it. **The E-014 class, one cell further in.**

## The repro baseline, and the version bump that moved eleven prebuilts

The workspace version is compiled into the binaries, so the bump moved **11** of them. The order the
procedure requires was followed and each step's own output read: **bump → `cargo xtask build` →
two-build run → delete → `--record-baseline` → verify the diff.**

* the two-build form first: **PASS, 34 artefacts identical** — determinism, which is the question that
  form answers;
* `--record-baseline` **refused** over the existing file, as designed (recording must never be a side
  effect of a check); the deletion is deliberate and was explicit;
* the re-recorded baseline's diff is **11 removed and 11 added digests, 22 lines**, matching exactly
  the 11 binaries `git status` reports and nothing else;
* then `--skip-build`: **PASS, 33 artefacts identical**.

**Recording before building would have looked like success and been the failure** — an empty diff,
with the previous version's digests absorbed. That trap is written into the procedure because the
0.27.0 cut hit it.

## What shipped

### RFC-0.50-001 — the kernel's decidable logic runs outside a boot (closes E-134)

`cargo test -p fjell-kernel` could not build: 19 errors, duplicate lang items, because a `no_std`
kernel binary cannot link a host test harness. So **27 `#[test]` functions had never been compiled** —
not skipped, not ignored, counted by nothing. **Nine were the user-pointer validator**, the predicate
deciding whether every pointer the kernel dereferences on a user's behalf lies inside that user's
address space.

They run now in **`fjell-user-ptr`, `fjell-lease` and `fjell-task`**: extraction, the pattern this
project had already used four times, not a `[lib]` over a kernel that cannot have one. **26 of the 27
bodies are byte-identical after the move and the 27th differs only in a `use` path** — brace-matched,
normalised and diffed by the architect against `b5d488d`, because "no assertion weakened" is a claim
and not a measurement.

**The lease seam is the wake.** `revoke` ended in a bare call reaching the task table, scheduler,
capability table and endpoint table on *every* successful revocation. The crate now **returns what must
be woken** and the kernel wakes, so all seven lease tests moved with **no text change at all**. A hook
trait — the implementer's first design — would have put the kernel's reach back inside the interface
the seam exists to cut.

`cargo test -p fjell-kernel` **exits 0 with nothing to run**, which is honest only because
**`dead-tests`** makes zero provably correct: `test = false` and that guard landed in one commit, and
the guard is red on the pre-change kernel with 31 hits and on a test planted in the real one. The
architect overruled the implementer's recommendation to leave the command failing, on the ground that
`error: could not compile … 19 errors` about lang items is not a red saying *"cannot"* — it is a red
saying nothing, in a form that reads as breakage.

**The second deliverable was the test that was never written.** 0.49's `ReadyQueue::remove` left the
`non_empty_mask` bit set on an emptied bucket and **hung the machine**, found by booting QEMU in a file
carrying three dead `#[test]`s — none of which would have caught it. `remove` has four tests now, shown
red against a reconstruction of the defect in a scratch worktree. **Not tested, and said:**
`Scheduler`'s own methods, the latch, `task/destroy.rs`.

### RFC-0.50-002 — the published interface is checked against the interface

Nine defects: seven the architect found by reading, two the gate found afterwards.

The Syscall Reference claimed **26 of 35 dispatched and 9 not**, where the truth was 35/35/0, and
**omitted seven live syscalls**. Its *"as-built at v0.21.3"* stamp was not even honest staleness: the
page carries `ClockNow`, added at 0.42, so the body had been maintained twenty milestones past its own
header's date. `kernel.md` disagreed with itself three ways — a stale 26 in its opening paragraph, the
same 26 over a table naming 27 and omitting 8, and a §6 asserting **"Interrupt syscalls are not
dispatched"**, false since 0.25, naming the wrong driver, over a path two release-gated profiles
exercise, and citing as authority the section of its own file that 0.49 had made say the opposite. The
gate then found `CapDelete`'s wrapper declared absent (it exists since 0.47) and `ipc_try_send`'s
declared present (it does not exist).

**`syscall-doc`'s red run was captured before any document was touched.** That ordering is the line's
evidence and exists only once.

**The instrument that declined this question named one that did not own it.** `doc_counts`'s scope note
excluded *"syscall counts already covered by `syscall-surface`"*; `syscall-surface` reads three source
files and a TOML, and no document. The note now names what does, and what remains covered by nothing.
**And the check 0.22 named for exactly this drift was built — as `syscall-surface`, aimed at the enum.**
The ground truth recorded in its own handoff, *"35 declared, 26 dispatched, 9 undispatched"*, is to the
number and the name what the Reference still said 28 milestones later.

### RFC-0.50-003 — a driver gives back the device memory it does not use

`MmioUnmap`'s only caller was the negative-test suite. `storaged` now scans **down** through
`BUS_OFFSETS` — the dead constant its own comment described while the loop ascended — and releases
every transport that is not blk, printing released, refused and unmappable separately so that
`0 released, 8 unmappable` cannot read as a clean scan. **8 → 1** mappings held by `storaged`;
**9 → 2** live once the drivers settle.

**The release runs in a gated boot**, which took a finding to arrange: the harness hard-coded blk's
`-device` before `extra_args`, and QEMU assigns virtio-mmio in reverse creation order, so blk was
always on the top transport and a descending scan would have released nothing anywhere. An **additive**
`pre_blk_args` lets `transport-order` place a NIC ahead of blk; **every existing profile's committed
`qemu-command.txt` is byte-identical**, proven by a test that refuses to pass on fewer than twenty of
them. Moving blk's `-device` instead — the tidier-looking fix — would have changed every command line
and silently relocated blk in every boot the project has recorded.

**That profile was GREEN under the mutation that mattered.** It first required only `storaged`'s own
*"released 1 unused mapping(s)"* — which a scan that *counted* a release it never made satisfies
identically, because a service's report is what the service believes. It now requires **the kernel's own
unmap line, exactly once**, distinguished from the suite's unmaps by page count and address. That line
is this RFC's Evidence, and it is citable only because E-135 was fixed in the same milestone.

### RFC-0.50-004 — the small items

**E-135 closed.** `write_summary` keys on the profile being release-gated, and **`qemu-records` compares
three sets** — not two, because *the two-set comparison E-135 itself proposed as "a one-line
comparison" would still have missed `fleet-demo`*, the profile it was filed for. `task-lifecycle` and
`mmio-unmap` were recorded **by the mechanism** from real runs; nothing hand-seeded. `fleet-demo` is
recordable by no writer and is **waived by name**, a waiver that fails the day it gains a record —
and writing that waiver surfaced that the demo's four markers had been declared in **three** places and
read in **one**, with the runner reading the copy no document pointed at. `verify` now reads the
profile.

**Criterion 9 classified and gated.** The cycle document now separates *correctness-gating* jobs from
*publishing* (`ci-pages` alone, the only job with `pages: write`, an `environment:` and a
`deploy-pages` step), and says which run each kind is read from. `release-records` requires a
push-labelled and a dispatch-labelled run id in a record's own criterion-9 section. **Section-scoped
and label-based because the architect's first specification, counted over the document, passes the very
record it was written for.**

**`service-table`** compares the service table with the tree, which was five programs short. Its
heading states the rule rather than a count now — and a rule with nothing checking it is the defect
this milestone exists to remove.

**And the criterion-9 gate needed one more thing, found by running it at a cut rather than against
history.** It could not pass at a release commit at all, because the runs it asks for are the tagged
commit's and the commit comes first. It now carries a **ceiling of one** — the version being cut is
not asked, every record below it is — with the reason written where the check is, not here. *A check
whose precondition cannot hold at the moment it runs is a fourth variant of this milestone's shape: not
evidence the assertion supplies itself, but evidence that does not exist yet.*

## What the architect got wrong, and who caught it

Recorded because the convention requires it, and because the implementer caught two of these before I
did:

* **Two stale `MmioUnmap` comments I ruled swept and had not** — 0.49 retired one syscall and
  dispatched its sibling; my sweep looked for the retired name and not for the claim about the other.
  Fifth instance of a retraction of mine missed by the wrong search. A **third** instance turned up in
  the implementer's sweep (`driver-uart`, false since 0.45).
* **E-135's headline figure, mine, added two sets together** — *"three of twenty-seven"*, where it is
  two of the 27 categories plus `fleet-demo`, outside them. Corrected in place with its date.
* **The criterion-9 gap at the 0.49.0 cut** — **E-137**, mine, in a record I alone write, and the third
  of mine to be wrong about its own subject.
* **A `services.md` miscount:** I reported *"29 claimed / 27 rows / 34 actual — three figures, no two
  agreeing."* The heading's 29 **matched** the table's 29 programs; my 27 was a count of rows. The
  implementer measured it correctly and the RFC carries the correction.
* **A lease-seam grep that filtered for a syntax and missed a function call**, which nearly had me tell
  the implementer their claim was overstated when it was understated.
* **A criterion-9 check I specified document-scoped**, which passes the record it was for.
* **Two malformed register edits of my own**, caught by `errata-tracking` (a `||` inside a Markdown cell
  split the row and emptied its tracking column) and `rfc-policy` (the `RFC:` bullet must carry `none`
  alone). Neither would have been caught by reading.
* **The criterion-9 gate I specified could not pass at a release commit**, and `release-rehearsal`
  found it **at this cut** — on the record being written. The check asks a record to name a push run
  and a dispatch run; **criterion 9's two runs are the runs for the tagged commit**, so they cannot
  exist until after the tag, which is after the commit the rehearsal judges. The implementer built it
  as specified and demonstrated it red against eleven historical records; neither of us ran it against
  a record that did not yet have its runs. Fixed here with a **ceiling of one**: the record whose
  version equals the workspace version is not asked, is named in the PASS line, and an exemption for it
  is reported as unnecessary. **The window is exactly one milestone and the next cut does ask** —
  which is how 0.49.0's gap was found in the first place. Two tests pin it, including one proving the
  ceiling is a ceiling and not a skip (a record *below* the one being cut with a single run is still
  red), because a blanket skip would pass the very shape E-137 records. **A code change after the
  verification run, so Gate 1 and Gate 12 were re-run**, not assumed.

## One shape, three times

**An assertion whose evidence the assertion itself provides.** `transport-order` asserting a service's
report of an unmap; a pin test grepping the file holding the assertion; a criterion-9 check counting
ids it would also have matched as decoys. All three were found by **mutating the thing the test was
about**, two of the three were mine, and RFC-0.50-004 names the shape and says plainly that no
instrument covers it.

## Tag and publish

**This section is written in two commits, and says so rather than claiming otherwise.** The release
commit carries everything a tag can point at; the tag's identity, the CI runs for that exact SHA, the
GitHub Release and the crate publishes can only be measured afterwards, so they are appended by a
follow-up commit. **That is the two-commit shape E-130's reorder leaves, and E-136 is the erratum for
describing it as an empty diff.**

**What is true of the tag, and is the property the reorder bought:** no source file, gate input,
instrument output or build artefact differs between the tagged commit and the commit that follows it.
The only difference is this section's measured rows, which cannot exist before the tag they describe.
That is checkable — **`git diff 0.50.0 HEAD --stat` names `releases/0.50.0.md` and nothing else** — and
**it does not mean the diff is empty.** This record does not say that it is.

## Known limitations at this release

`docs/src/releasing/v1-limitations.md` carries **31** rows and the register **7 accepted, 0 open**. The
two that changed at this cut:

* **Row 30** recorded that a newly gated profile could not record its first marker artefacts. **That is
  fixed**, and the row now records the bound that remains: `fleet-demo` is recordable by no writer and
  is waived by a checked waiver.
* **Row 31 is new** (E-138): a negative-test fixture can make two production services fail mid-boot, in
  a tier the release gates on. It has not recurred in any `test-all`; a green suite there is the
  scheduler's current choices and not an invariant.

**Banked for 0.51:** the page-table walker with the restart policy and the quota as one design — and
line 1 has now given it `TaskTable`'s reuse mechanism tested on the host, which is why it was
sequenced this way; retiring the `ALL_NON_META` blanket at its nineteen grant sites; `DELEGATE_ONLY`,
a fourth deferral; **E-138's fixture race**; `Scheduler`'s untested methods; and `DmaRevoke`, first
among the nine wrappers with no production caller.
