## What this release is

Two RFCs, **five errata closed** (**E-078**, **E-081**, **E-082**, **E-083**,
**E-084**). A service that had never been built into the image now runs and
is asked a question; the answer it gives is honest and almost entirely
negative; and the gate that reports "0 warning lines" can no longer be
bought with a crate-level `allow`.

**Every availability flag in the bundle this release can produce reads
`false`**, disclosed in the CHANGELOG in its own words — the condition the
architect attached to this cut. A bundle still cannot leave the node
(push capability uninstalled); the measurement head still cannot be
obtained at all, for any consumer (**E-085**, found and filed this
milestone, unscheduled).

## What shipped

### RFC-0.37-001 — a bundle gets asked for and produced

`fjell-fleetd` was not merely a stub with a dead event loop (**E-081**'s own
original description): it had no `ImageId`, was absent from the build list
and the kernel's embedded image table, and its own runtime file had no
`_start` symbol — it had never been cross-compiled and linked as a bootable
image, confirmed by a control (removing its panic handler made the
cross-compile fail outright). It now runs: a real event loop, never
exiting, asking `fjell-diagnosticsd` for a bundle on a console-byte
trigger — not a real `RemoteDiagRequest` over the network, which stays out
of scope.

`fjell-diagnosticsd`'s receive capability is installed for the first time
(**E-078**), exposing a tag mismatch nothing had ever triggered:
`measuredd`'s measurement-head query used numbers the server never
answered, already assigned elsewhere in the shared protocol table
(**E-083**) — demonstrated failing against the real `measuredd` before
being fixed, and closed on both sides (`diagnosticsd` and
`secure-transportd`'s own tag enum now read one shared declaration).
Sweeping the defect before writing code against it found that fixing the
tags alone would have landed a sequence number inside a 32-byte digest
field and reported it available — escalated and ruled before any of that
shipped: the capability stays uninstalled (**E-085**, filed this
milestone), and the measurement-head field reads honestly unavailable.
Closes **E-078**, **E-081**, **E-083**.

### RFC-0.37-002 — instruments that cannot be bought

Thirteen crates carried a crate-level lint suppression; nine suppressed
nothing and were deleted, three narrowed to item-level allows each stating
its reason, one kept crate-level with its reason stated. The thirteenth,
`fjell-netd`'s, was hiding a complete, finished IPC event loop a suppressed
`unreachable_code` lint would otherwise have named (**E-084**) — kept, not
deleted, moved into a function the service never calls so a reader meets it
as `dead_code` the compiler names explicitly. `cargo xtask build` now also
reports a count of surviving crate-level allows, a record figure that never
fails the build; today, one. Closes **E-082**, **E-084**.

## What this release does not claim

- **That a bundle can leave the node, or that a measurement head can be
  obtained.** Neither is true — the push capability stays uninstalled
  (fails closed, every time) and `measuredd`'s reply protocol cannot carry
  a whole chain digest for any consumer (**E-085**). This release makes the
  asking machinery real and the answer honest; it does not make the answer
  non-empty.
- **That `fjell-audit-format`'s or `fjell-net-format`'s on-wire layouts
  have a generated description.** They do not — **E-073**, pending a
  kernel-side change to where `sys_audit_drain` writes.
- **That a clean dependency check describes what Fjell OS ships.** The
  published crates and the kernel have no third-party dependencies at all;
  the check covers tools, tests, benchmarks and the development-grade
  crypto crate, and says so in its own output.
- **That CI gates the release.** Criteria 9 and 11 *record* CI; every gate
  runs locally.
- **Cross-machine reproducibility**, as at every previous release.
