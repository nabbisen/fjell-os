**E-133**, the last four filed inside the milestone. The register stands at **132 entries, 5 accepted,

the product has not been placed on the market.

The same row needed its scope stated rather than inferred. *"A task binds only a lease it created"*
constrains **`sys_cap_bind_lease`**, the user-facing bind. It is **not** a statement that every
capability a task holds is bound to a lease that task created, and since 0.48 most are not: `spawn()`
binds a task's boot capabilities to a lease its **spawner** owns, which is the kernel's own binding
and not a syscall a task may make.

**And a published page was silent about the milestone's whole subject.**
`docs/src/external-design/capability-lease.md` describes the as-built lease model and did not mention
boot leases at all — not false, but a page whose purpose is to say what the model *is*, omitting that
every task now has a lease. It now records that, `MAX_LEASES` 128, the two fixtures that keep slot 0
unbound and why, and the bound that remains.

## What shipped

### RFC-0.48-001 — a bootstrap capability can be taken back (closes **E-093**)

**The premise `RFC-v0.7.4-003` removed recursive revocation on — *every meaningful capability has a
lease* — was never enforced**, so for the life of the project **no authority granted at boot could be
withdrawn by anyone**: not the holder's own `cap_revoke`, which deletes descendants and not the
capability it names; not another task's, because capability revocation never crosses a CSpace; not
lease revocation, the only cross-task primitive, because those grants had no lease. The capabilities
affected are the most privileged in the system.

`spawn()` now creates a **boot lease owned by the spawner** before any frame is allocated, and **one
pass binds every capability the task holds** — so no `lease: None` literal had to be edited and a new
grant cannot forget. It lives in the subject's TCB, is revoked when the subject exits or faults, and
is deliberately **not** ended by its owner's death: `init` exiting must not strip every service it
started.

**`MAX_LEASES` 32 → 128**, in `fjell-abi` so `neg-test` derives its bounds from it rather than a second
literal, with a compile-time assert that the table holds **one lease per task plus one delegator's
whole quota**. **0 Verus obligations changed** — the lease model has no capacity token.

**Two named exceptions remain**, each with its reason in `bootstrap-leases`: `neg-test`'s and
`sample-service`'s slot 0, because those fixtures bind capabilities to leases *they* create and a
capability binds **once** (E-090).

### What the architect got wrong in this line, twice

**The motive was unachievable.** The handoff's example — *"an operator who decides a service must lose
its MMIO window"* — cannot be delivered by any option, because **`MmioUnmap` is declared in the ABI
and has no dispatch arm**. The implementer established that *before* building.

**And the generalisation that replaced it over-reached.** I accepted *"revocation does not reclaim
authority that became a resource (MMIO mapping, DMA frame)"* at stage 1 and corrected it at stage 2:
**DMA is reclaimable.** `sys_dma_revoke` is dispatched, requires `DmaRegion` + `DMA_REVOKE` through
the funnel, and unmaps the owner's page **verified**. The asymmetry is **MMIO versus DMA** — the more
useful finding, because the project already knows how to do this for one resource.

**The capacity recommendation was mine and the measurement was theirs.** I wrote *55 grant sites*
from source literals; a real boot has **31 holders**, runtime leases share the table (peak live 17),
and `MAX_LEASES_PER_OWNER` = 16 rules out any single-owner design. **I also invented a constraint that
does not exist** — that enlarging `MAX_LEASES` would disturb the Verus lease model — and withdrew it
after checking: the model has no capacity token at all.

**The limit is held by a guard, not a scenario.** A boot test would have needed an *unbound*
`MmioRegion` and so a third fixture exemption. `bootstrap-leases` instead **fails the day `MmioUnmap`
is dispatched**, so the claim must be restated when the premise changes. **Two exemptions with reasons
is a design; three to host a test is a habit.**

### RFC-0.48-002 — a safety annotation describes the operation it annotates (closes **E-131**)

`unsafe-audit` reported **291 sites, 0 missing** and Gate 2 passed on it. **It could not see 49
declarations:** 41 `#[unsafe(no_mangle)]`, 1 `#[unsafe(naked)]`, 6 `unsafe extern "C" fn` where
`extern "C"` sits between `unsafe` and `fn`, and **one `unsafe impl<T>`**.

**That last one is the finding, and the cause is one character.** The scanner matched
`"unsafe impl "` **with a trailing space**; nine declarations exist, eight match, and the ninth is
`unsafe impl<T> Sync for KS<T>` — **a `Sync` soundness claim about the kernel-state wrapper that every
`get_kernel_state()` call in the kernel goes through.** And `#[unsafe(naked)]` sits one line above the
trap entry stub, so **two invisible declarations shared the function every trap enters through.**

Now **344 sites, 344 commented, 0 missing**, and a `category=` its operation does not support is
refused. New categories `linker-symbol` and `symbol-export` close a taxonomy gap where six sites
claimed `phys-id-map-assumption` for the address of a linker symbol.

**The architect's count of 48 was wrong** — I grepped the attribute I already knew instead of the
attribute *shape*, inside an entry about an instrument that matches too narrowly, and the implementer
restored 49. **The sequencing inversion was theirs and better than my constraint:** land the gate
first with a seeded exemption list the sweep shrinks, so **the list's length is the sweep's progress**.
In the event the sweep finished in the same stage: **0 seeded, 4 permanent.**

### RFC-0.48-003 — a Release is published from a tag that has been checked

On the owner's request, and on the owner's ruling that it publish rather than draft: **the tag is
already the authorization, so publishing from it bypasses nothing**, and the care belongs in the
trigger. Notes come from the CHANGELOG section for that exact version; the record is **linked, never
copied**. The bare-tag convention is enforced; `permissions: {}` at the top with `contents: write` in
exactly one job; every action pinned by a commit SHA resolved from the API.

**Three things the architect's design could not have known, all found by measurement:**

* **The correspondence it gates does not hold for history** — of 105 bare tags, 35 have a CHANGELOG
  section and 27 a release record; total **from `0.21.3` on**, so the floor is **derived**.
* **The tag checks cannot be a `consistency-check` subcheck**, which `release-handoff.md:298` defines
  as *a pure function of the committed tree* — tags are not in the tree, and at Gate 12 the new tag
  does not exist.
* **The asset attachment I asked for was impossible:** Step 12b signs the archive *after* the tag with
  the offline key, so at push time the signature does not exist.

**Precondition 5 — the tag-signature check — was withdrawn before the cut, and the reason is mine.**
The owner asked only for Releases; **I invented it.** It caught nothing but an accidentally unsigned
tag, stopped nobody with push access (who could change the committed key too), and **duplicated a step
the cut already performs**: `git tag -v`, before the push. The table went from seven rows to six live;
`release-preflight` from nine numbered checks to eight. The implementer then **added `git tag -v` to
the checklist**, because the assurance now rests on a step that existed only in the architect's habit —
and ran it with a control that needed `GIT_CONFIG_GLOBAL=/dev/null`, their own config signing every tag.

**Neither `gh release create --verify-tag` nor GitHub's "Verified" badge is a signature gate** — the
flag aborts if the tag is absent from the remote (checked against `gh`'s own help, not assumed), and
the badge is visible, not enforced.

### The small item, and the cycle defect the cut found in itself

**E-130 closed.** The pre-publish landing-page re-read moved **before** the tag, because
`cargo publish` packages the working tree and a correction found after the tag put the publish ahead
of it — **twice in three cuts**. Only the logo-URL fetch still needs the tag. A publish precondition in
the cycle requires `HEAD` to be the tag's commit with a clean tree and **was run against the real
0.47.0 failure, which it refuses**.

**E-133 — and this one is a misdiagnosis of mine in a released record.** `ci-pages` ran on every
`main` event but `pull_request`, so **criterion 9's dispatch re-deployed Pages for a tree the push run
had already deployed**, and in the queued run `deploy-pages` reports **`Found 0 artifact(s)`** for an
artifact its own run finalised seconds earlier. At 0.46.0 I called that transient and re-dispatched;
**that re-dispatch happened to pass, and I generalised a single success into a mechanism.** At this cut
the re-dispatch failed identically. `ci.yml`'s concurrency note had said since 0.32.0 that both
deploys serve the same commit and the second is redundant — the redundancy was known; that it *cannot
succeed* was not. **`ci-pages` no longer runs on `workflow_dispatch`.** `releases/0.46.0.md` keeps its
false claim, because released records are not rewritten; E-133 is what makes it findable.

## Known limitations at this release

**132 entries, 5 accepted, 0 open**, every accepted erratum referenced in `v1-limitations.md`.

* **MMIO mappings cannot be reclaimed** — `MmioUnmap` is declared and dispatched nowhere (row 7), and
  `bootstrap-leases` fails the day that changes.
* **E-073** — two `#[repr(C)]` wire layouts described by nothing a gate compares; closing
  `AuditRecordBin` honestly means changing where the kernel writes every audit record.
* **E-095** — three of the measurement chain's four events are `0xAB` placeholders.
* **E-122** — the v0.4 network plane is three non-functional images.
* **E-004** — no hardware has ever been booted.
* **E-014** — the standing class these milestones chip at; 0.48's chip is the audit's category rule.
* **The readiness matrix's "20 obligations" matches none of the four figures `verus-count` states**
  (19 / 26 / 12 / 17), for a **fourth** cut. **A cell asserting a figure nothing can produce is exit
  criterion 8's own subject**, and it survives because the fix is the owner's ruling, not an edit. The
  architect's recommendation is **19** — prover-verified items in release-required targets, derived.
* **`DELEGATE_ONLY` is still not taken.** Its prerequisite *is* satisfied now; a negative right
  deserves its own RFC against a `Delegable` kind and an install-source table.
* **A boot lease outliving its owner can be revoked only by a `LEASE_REVOKE_ANY` holder**, and that
  rests on task slots never being reused — `TaskTable::remove` has no callers, guarded by
  `bootstrap-leases` premise 6, with a **generation-aware owner** named as the successor and not built.

**No accepted-risk statement is written for this release.** No gate that should have blocked was left
unpassed, and the one red job this cut produced was a configuration defect, fixed rather than accepted.
